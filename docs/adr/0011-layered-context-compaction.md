# ADR 0011：分层上下文压缩与 Anchor Ledger

- 状态：已采纳
- 日期：2026-11-19

## 背景

长会话会超过模型上下文窗口。简单截断会丢掉任务目标、约束、已执行命令和错误，导致 Agent 重复劳动或做出与既有决策冲突的操作。另一方面，原始 Transcript 是审计与恢复的事实来源，压缩不能删除它。

## 决策

压缩是 Transcript 之上的**只读视图变换**：压缩结果写入 `compactions` 表与 artifact，`ContextBuilder` 在组装请求时按顺序应用，原始 `messages` 行永不修改。

预算为 `context_window - max_output_tokens - 安全余量 - 系统提示 - 工具 Schema`。估算 token 达到 `trigger_ratio`（默认 0.82）时触发，压缩目标是留出余量（`trigger_ratio - 0.20`）。

分层执行，每层都重新估算：

- **L1 工具输出归档**：最近 `keep_recent_turns` 个用户轮次之外、长度超过阈值的工具结果写入内容寻址 artifact，Transcript 视图中替换为头部预览和 artifact 引用。artifact 读取时校验 SHA-256。
- **L2 确定性摘要**：把较老轮次替换为结构化摘要（目标、约束、决策、工具活动、错误、状态）。不依赖模型，永远可用。
- **L3 模型摘要**：把同样的内容交给模型生成压缩摘要；空输出、异常或超时都视为失败并回退 L2。连续失败达到阈值后熔断：`disabled_until_turn` 实际保存“剩余压缩尝试次数”，而不是绝对 turn 序号，因此跨 Run（turn index 会重置）也能正确恢复，不会永久禁用。
- **L4 检查点重置**：先创建 Checkpoint，再把旧历史替换为重置说明；锚点与最近轮次保留。Checkpoint 创建失败时不执行重置。

L2/L3 生成的新摘要会记录其覆盖的旧摘要 ID（`supersedes`），应用时跳过被取代的旧摘要，避免重复叠加。压缩范围只在完整用户轮次边界切分，永不拆散 assistant tool_call 与其 tool result。

**Anchor Ledger** 保存跨压缩必须保留的关键事实：首个用户目标、包含约束关键词的用户消息，以及用户手工加入的锚点。锚点以独立 pinned system 消息注入每次请求，L4 也不会清除它们。

出现以下情况时不会破坏运行：L3 失败回退 L2，且仍允许 L4 运行；所有层都压不到阈值时，交给现有 Builder 做最后截断；仍超限则抛出 `ContextOverflowError`，由 Runtime 以结构化停止原因结束。

如果“受保护的最近轮次 + Anchors”本身就超过触发阈值，压缩旧历史无法让请求达标，此时本轮最多执行 L1/L2，并记录 “target unreachable”，避免每轮重复 L3 模型调用与 L4 重置。

## 影响

- Transcript 完整可审计，压缩可追溯（每条 compaction 记录范围、前后 token、artifact）。
- 压缩是确定性的、可重放的；同一 Transcript 与设置得到同一视图。
- artifact 增加磁盘占用；当前没有自动 GC，由用户/后续阶段清理。
- L3 摘要质量依赖模型；错误事实可能被压缩，因此 L2 的确定性事实与锚点优先保留。
- token 估算仍是启发式，不保证与供应商计费一致。

## 备选方案

- 直接截断最老消息：拒绝；会丢失目标与约束。
- 修改/删除原始消息：拒绝；破坏审计与恢复。
- 只做模型摘要：拒绝；模型不可用时无法压缩。
- 每轮都压缩：拒绝；成本和延迟不可接受。
