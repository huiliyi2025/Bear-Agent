# ADR 0009：本地哈希链安全审计

- 状态：已采纳
- 日期：2026-11-19

## 背景

运行事件适合追踪，但不是安全账本。我们需要一份可事后验证的 append-only 记录，覆盖策略、审批、Sandbox 与 Claim 决策。

## 决策

使用现有 `audit_log` 表与 `prev_hash`/`hash`。每条记录的哈希覆盖前一条哈希、session ID、actor、action、resource、规范化 detail JSON 与时间戳，并序列化为无歧义 JSON 对象。追加使用 `BEGIN IMMEDIATE`，因此单个 SQLite 数据库可跨进程串行化链。`bear audit verify` 重算链并报告第一条坏记录。

审计追加是安全相关的：工具动作执行前追加失败会中止动作；命令执行后追加失败会暴露给用户，但无法撤销。

## 影响

- 可检测意外编辑/删除与朴素篡改。
- 本地哈希链无法防御重算整条链的写入者；没有实现外部锚点/签名。
- 链按数据库全局，而不是按会话。
- 审计详情在存储前脱敏。

## 备选方案

- 只依赖 OTel/远程审计：拒绝作为唯一记录；本地运行必须离线可用。
- 不做审计：拒绝；安全决策将不可追踪。
- 区块链/外部服务：超出范围，且不能替代本地完整性。
